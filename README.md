# Roguelike
지하민 팀 프로젝트. 2D 횡스크롤 로그라이크.

# 커밋 메시지 작성 규칙

프로젝트의 커밋 이력을 일관되고 명확하게 관리하기 위한 커밋 메시지 작성 규칙입니다.

## 1. 커밋 메시지 형식

커밋 메시지는 **커밋 타입(Commit Type)**과 **커밋 제목**으로 구성합니다.

```text
[커밋 타입] 커밋 제목
```

### 작성 예시

```text
[Feat] 플레이어 이동 기능 추가
[Fix] 플레이어 체력 감소 오류 수정
[Docs] 프로젝트 README 내용 수정
[Refactor] 플레이어 공격 로직 리팩터링
```

## 2. 작성 원칙

- 하나의 커밋에는 가능한 한 **하나의 작업 단위**만 포함합니다.
- 커밋 제목은 작업 내용을 **간결하고 명확하게** 작성합니다.
- 커밋 제목만 보고도 어떤 작업을 했는지 알 수 있도록 작성합니다.
- 커밋 타입은 영문으로 작성하며, **첫 글자는 대문자**로 표기합니다.

## 3. 커밋 타입

| 커밋 타입 | 설명 |
|---|---|
| `Add` | 파일, 리소스, 설정 등 새로운 요소를 처음 추가한 경우 |
| `Feat` | 기존 시스템에 새로운 기능을 추가한 경우 |
| `Fix` | 버그 또는 오류를 수정한 경우 |
| `Docs` | README, 문서, 주석 등을 수정한 경우 |
| `Style` | 코드 동작에 영향을 주지 않는 서식이나 스타일을 수정한 경우 |
| `Refactor` | 기능 변경 없이 기존 코드 또는 시스템 구조를 개선한 경우 |
| `Test` | 테스트 코드를 추가하거나 수정한 경우 |
| `Chore` | 빌드, 패키지, 설정 파일 등 기타 유지보수 작업을 한 경우 |

## 4. 타입별 작성 예시

```text
[Add] 플레이어 스프라이트 리소스 추가
[Feat] 플레이어 대시 기능 추가
[Fix] 점프 중 충돌 판정 오류 수정
[Docs] 설치 방법 문서 추가
[Style] 코드 들여쓰기 및 공백 정리
[Refactor] 플레이어 공격 로직 구조 개선
[Test] 플레이어 이동 기능 테스트 추가
[Chore] 프로젝트 패키지 버전 업데이트
```

## 5. 권장 사항

### 좋은 커밋 메시지

```text
[Feat] 플레이어 체력 회복 기능 추가
[Fix] 적 처치 후 점수가 중복 반영되는 오류 수정
[Refactor] 인벤토리 아이템 정렬 로직 분리
```

### 피해야 할 커밋 메시지

```text
수정
작업함
버그 고침
여러 기능 추가 및 오류 수정
```

커밋 메시지는 작업 목적과 변경 내용을 명확하게 전달할 수 있도록 작성합니다.
